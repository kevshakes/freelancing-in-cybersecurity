# Showcasing CTF Results & Certifications

Certifications and CTF ranks are proof clients can verify quickly — use them well.

> For a full breakdown of top certifications (including the ISACA lineup and the new CCOA), see [`07-certifications/`](../07-certifications).

## Certifications

- List certifications consistently across GitHub profile, LinkedIn, and every platform profile — same wording, same order (most relevant first)
- Link to verification pages where the issuer provides one (AWS, CompTIA, etc.) — verifiable claims build more trust than a static badge image
- Don't just list the cert name — add one line on what it means practically (e.g. "AWS Security Specialty — cloud security architecture and incident response")
- In-progress certifications are worth mentioning too ("Currently completing X") — it signals momentum

## CTF platforms worth showcasing

- **TryHackMe** — good for showing structured, guided learning progress; link your public profile
- **HackTheBox** — strong signal for hands-on offensive skill; rank and machine count are meaningful to technical clients
- **CTFtime** — if you've competed in team CTFs, link results and writeups

## How to present CTF results to non-technical clients

Most clients won't know what a HackTheBox rank means. Translate it:

> "Ranked in the top X% on HackTheBox, a platform where security professionals practice real-world attack techniques in controlled environments — this reflects hands-on offensive security skill, not just theory."

## Portfolio page structure (GitHub profile README or personal site)

```markdown
## Certifications
- [Cert Name] — [Issuer] — [Verify link] — [one-line relevance]

## CTF & Practical Experience
- [Platform] — [Rank/Stat] — [Profile link]
- [Notable challenge/writeup] — [link to writeup]

## Featured Write-ups
- [Title] — [one-line summary] — [link]
```
