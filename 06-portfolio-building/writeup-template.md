# Write-up Template (GitHub / Portfolio)

Use this structure for a home-lab pentest, CTF walkthrough, or sanitized project summary. Publish to GitHub as a markdown file or repo README.

```markdown
# [Project/Challenge Title]

## Overview
One paragraph: what this was, what environment/target, what you set out to do.

## Objective
- Specific goal(s) of the exercise (e.g. "gain initial access and escalate to admin")

## Tools Used
- List tools, frameworks, and methodology used (e.g. Nmap, Burp Suite, manual review)

## Approach
Step-by-step walkthrough of your methodology — recon, enumeration, exploitation,
post-exploitation. Include commands and screenshots where relevant (redact anything
sensitive or belonging to a real client/organization).

## Findings
What you found — vulnerabilities, misconfigurations, weaknesses — described clearly,
with severity if applicable.

## Remediation
What you'd recommend to fix each finding. This section is what separates a
"hacker" writeup from a "hireable professional" writeup — clients pay for the fix,
not just the break.

## Lessons Learned
1–2 sentences on what this taught you or what you'd do differently.

## Disclaimer
Only if based on a real client engagement: confirm this is sanitized/anonymized
and shared with permission. Never publish real client names, IPs, or data.
```

## Where to publish

- A dedicated GitHub repo per project, or one `writeups/` folder in a single portfolio repo
- Pin your best 2–3 write-ups on your GitHub profile
- Link directly to specific write-ups (not just your GitHub homepage) in proposals and platform portfolios
